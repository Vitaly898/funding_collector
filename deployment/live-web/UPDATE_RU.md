# Быстрое обновление Funding Collector (не приложения Contour)

Этот скрипт **не запускался на VPS** при разработке. Локальные тесты используют
поддельные команды Docker/Git. Реальная сборка и rollout требуют Docker daemon,
прав оператора и отдельного разрешения на точную опубликованную ревизию.

## Одна команда после публикации одобренного SHA

В чистом доверенном клоне `~/apps/funding_collector` (оператор `qaagent`):

```bash
sudo -v && python3 deployment/live-web/update.py ПОЛНЫЙ_40_СИМВОЛЬНЫЙ_SHA --repo ~/apps/funding_collector --docker-sudo
```

`sudo -v` запрашивает пароль в вашей консоли. Флаг `--docker-sudo` повышает
права только отдельных Docker-команд; Git, файлы сборки и блокировка остаются
принадлежащими `qaagent`. Без флага требуется уже настроенный доступ к Docker.
Скрипт не запрашивает пароль скрытым subprocess: при истёкшем sudo-ticket Docker-команда
завершится отказом. Перед обновлением используйте свежий `sudo -v`.

`master`, сокращённый SHA, локальный неопубликованный commit и произвольный
скачанный объект не принимаются. Ревизия должна быть **точным tip одной из
свежеполученных веток** `origin` с URL
`https://github.com/Vitaly898/funding_collector.git`. Никаких merge, reset или
переключений рабочего дерева: сборка из отдельного detached worktree.
Первое получение самого скрипта из одобренной ревизии — отдельный ручной шаг;
старый checkout без этого файла не может выполнить эту команду.

## Перед подтверждением

1. В UI заблокируйте worker, дождитесь завершения операции.
2. На **обеих биржах** вручную сверьте фактические позиции, все ордера и fills.
   Блокировка/перезапуск не означает cancel или flatten.
3. Скрипт сначала соберёт `funding-collector-live-web:<sha12>`, выполнит
   `pip check` и nonprivate import-smoke без сети и без data volume.
4. До остановки старого контейнера потребуется вручную ввести:
   `WORKER STOPPED; VENUE ORDERS AND POSITIONS RECONCILED`.

Пароли, seed, API keys, passphrase и приватный journal скрипту не нужны.
Не передавайте их через аргументы или окружение.

## Что сохраняется и что запускается

- Только `funding-live-web`; внешний именованный volume
  `funding_live_web_data:/data` **не создаётся заново и не удаляется**.
- Старый контейнер сохраняется остановленным под уникальным именем
  `funding-live-web-recovery-...`, включая исходный image ID и конфигурацию.
- Новый контейнер: `--network=host`, bind **127.0.0.1:18765**,
  `--memory=1g --memory-swap=1g --cpus=1 --pids-limit=64`, readonly root,
  tmpfs `/tmp` 64 MiB, cap-drop ALL, no-new-privileges, core=0,
  `--restart=no`. Owner, encrypted keys и ledger остаются в прежнем volume.
- Проверяется `/api/health` из **нового контейнера**, без login/private API.
  Никакой торговли и auto-resume: authority после рестарта заблокирована.
- При ошибке нового запуска/health новый контейнер удаляется **без `-v`**,
  старый возвращается под исходным именем и запускается с его сохранённой
  конфигурацией; повторно проверяются исходный image ID, running и health.
  Ошибка `docker run` до создания candidate не блокирует rollback.
  Не запускаются две копии worker с одним volume.
- Нет `docker prune`, `compose down`, Docker socket mount, owner `init`,
  очистки journals, вмешательства в Hermes, Contour или другие контейнеры.

## Ограничения и аварии

- Скрипт намеренно отказывается от неизвестных mount/network-конфигураций,
  грязного дерева, неработающего старого контейнера и нескольких работающих
  контейнеров с этим volume. Он рассчитан на указанный существующий VPS setup,
  не является универсальным installer/migrator.
- Файловая блокировка сериализует запуски этого скрипта. Оператор не должен
  параллельно вручную запускать другие контейнеры с тем же volume.
- Успешный health-check — только HTTP-жизнеспособность, **не** SDK/account/
  exchange acceptance. Rollback не откатывает содержимое volume. Сначала
  независимо проверяйте совместимость формата данных новой версии; destructive
  migrations этим rollout не поддерживаются.
- При kill -9/падении хоста автоматический rollback не гарантируется. Сохранённый
  recovery-контейнер нужен для ручного восстановления. Если rollback не удался,
  остановитесь, проверьте владельца volume и loopback-порт, затем восстанавливайте
  **только одну** старую копию. Никогда не вызывайте `init`/`rm -v`.
- Если stop вернул неоднозначную ошибку, скрипт не предполагает, что ордера
  отменены; требуется ручная проверка контейнера и обеих бирж.

Тест: `python -m pytest tests_fc/test_live_update.py -q` — fake Git/Docker,
успех, build failure, health failure + rollback, dirty tree, неверный SHA tip,
неподтверждённый rollout. Настоящий Docker rollout здесь не выполнялся.
